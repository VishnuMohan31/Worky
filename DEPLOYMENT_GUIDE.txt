WORKY DEPLOYMENT GUIDE
======================

This guide explains how to properly deploy Worky in different environments.

---
LOCAL DEVELOPMENT
---

1. Ensure .env.local exists with local configuration:
   VITE_API_BASE_URL=http://localhost:8007/api/v1

2. Start services:
   cd Worky
   ./App_Development_scripts/start_all.sh

3. Access:
   UI:  http://localhost:3007
   API: http://localhost:8007

---
PRODUCTION DEPLOYMENT (Remote Server: 62.171.191.132)
---

1. Ensure .env.production exists with production configuration:
   VITE_API_BASE_URL=http://62.171.191.132:8007/api/v1

2. Push code to GitHub:
   git add .
   git commit -m "Update deployment configuration"
   git push origin main

3. On remote server, pull latest code:
   cd /opt/Worky
   git pull origin main

4. ONE-TIME FIX: If you have an existing database with different password:
   docker exec -it worky-postgres psql -U postgres -c "ALTER USER postgres WITH PASSWORD 'postgres';"
   docker restart worky-api

5. Deploy:
   chmod +x deploy_contabo.sh
   ./deploy_contabo.sh

6. Access:
   UI:  http://62.171.191.132:3007
   API: http://62.171.191.132:8007

---
IMPORTANT NOTES
---

- The UI is built with the API URL hardcoded into the JavaScript bundle
- You MUST set VITE_API_BASE_URL before building
- Local dev uses .env.local
- Production uses .env.production
- The deploy_contabo.sh script automatically loads .env.production
- Always rebuild UI when changing API URL (--no-cache flag is used)

---
TROUBLESHOOTING
---

Issue: UI calls localhost instead of production IP
Fix: Rebuild UI with correct environment:
     docker compose down
     docker rmi worky-ui
     docker builder prune -f
     VITE_API_BASE_URL=http://62.171.191.132:8007/api/v1 docker compose build --no-cache ui
     docker compose up -d

Issue: Database password authentication failed
Fix: Update postgres password in existing volume:
     docker exec -it worky-postgres psql -U postgres -c "ALTER USER postgres WITH PASSWORD 'postgres';"
     docker restart worky-api

Issue: Changes not reflected after rebuild
Fix: Clear Docker cache:
     docker builder prune -f
     docker rmi worky-ui
     Then rebuild

---
VERIFICATION
---

After deployment, verify:

1. API is healthy:
   curl http://62.171.191.132:8007/health

2. UI contains correct API URL:
   docker exec worky-ui sh -c "grep -o 'http://[^\"]*8007' /app/dist/assets/index-*.js | head -3"
   Should show: http://62.171.191.132:8007

3. Login works:
   Open http://62.171.191.132:3007
   Login with: admin@datalegos.com / password
